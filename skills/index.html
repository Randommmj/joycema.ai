我每次上哈佛的课之前，都会用这个技能做预习：把案例原文和老师的问题交给 AI，它先帮我把案例梳理清楚、用中英双语逐题作答（英文直白到课堂上能直接说出口），再按固定结构写成一篇预习文章，最后配上手绘铅笔风格的插图。这个网站上的「哈佛预习」系列，都是这样写出来的。

它会交付

  • 一份预习问答：案例梳理、主要数据、人物关系、Tension，以及逐题的中英答案——留给自己上课用；
  • 一篇可以公开发布的文章：标题、梗概、「我的思考」、借鉴和写在课前，结构固定；
  • 头图和正文配图的提示词与选图方法。

怎么用

  1. 下载下面的压缩包并解压，得到 harvard-case-preview 文件夹；
  2. 放进你的技能目录：Claude Code 放在项目的 .claude/skills/ 下；Cursor 放在 .cursor/skills/ 下；在 Claude 应用里，可以在设置的技能页面上传这个压缩包；
  3. 打开 SKILL.md，按文末「个性化设置」改几处占位符（存放目录、作者名、学校）；
  4. 把案例 PDF 和老师的课前问题发给 AI，说一句「帮我做哈佛案例预习」。

不是哈佛的课也能用：把标题前缀和配图里的建筑换成你自己学校的就行。

哈佛案例预习 (Harvard Case Preview)

一句话触发："帮我做哈佛案例预习" + 案例文件 + 老师的提问。交付三样东西：

  1. 预习问答（课堂用，私人）：案例梳理 + 中英双语逐题作答
  2. 预习文章（可公开）：按固定结构写成的一篇 Markdown 文章
  3. 配图：头图 1 张 + 正文图 1–2 张，手绘铅笔风格

作者：Joyce Ma（joycema.ai）。这是她在哈佛商学院 OPM 课程中每次课前使用的流程的公开版。 第一次使用前，按文末「个性化设置」改几处占位符即可。

输入

项 来源 缺失时
案例原文 用户提供的 PDF / docx 让用户给文件，不要凭记忆写案例
老师的提问 用户粘贴的 Session Preparation / 课前问题 若未给，问一次；仍没有就按「案例结尾的决策点 + 本课主题」自拟 3–4 问，并标注"自拟"
授课老师与课程 文件名或用户说明 问一次；文章开头两行要用

案例必须通读到最后一页。附表（Exhibit）里的数字常常是答题和写稿最硬的素材。读长 PDF 时分两次读（正文 + 附表），不要只读前半。

工作流

- [ ] 1 通读案例全文与附表；确认老师、课程
- [ ] 2 案例梳理（梗概、主要事实与数据、关键人物与关系、Tension），写在问答文件最前面
- [ ] 3 双语问答（先英后中，逐题），存文件 + 回复里给出
- [ ] 4 写预习文章（标题规则 + 结构模板见下），存文件
- [ ] 5 配图：头图 1 张 + 正文图 1–2 张，插入 Markdown
- [ ] 6 发布前自查（见第 4 节），给出文件路径

1. 案例梳理 + 双语问答

格式见 references/qa_format.md。要点：

  • 先梳理再作答：问答文件第一节是 ## 案例梳理，四小节固定——梗概（按时间顺序讲完故事，不夹判断）、主要事实与数据（表格，带出处，推算写算式）、关键人物与关系（表格，标出谁有决策权、谁反对、谁是外部压力）、Tension（3–6 条，老师的决策题所在的那条放第一）。后面每题的数字和选边都从这一节取。这一节只进问答文件，不进文章。
  • 逐题：每题先 English 再 中文，两边内容对等，不是互译缩写。
  • 英文直白：短句、常用词、不堆术语；EBITDA、TAM 这类必要术语留着，其余用大白话。目标是课堂上能直接说出口。
  • 数字锚定：每个判断尽量带案例里的数字，并写清推导（如"7 × 23 万 + 51 × 19 万 ≈ 1100 万"）。
  • 末尾两段固定：Lessons / 启示（3–6 条）和 Inspiration for My Work / 对我自己工作的联想。联想部分可以写得很具体、引用你自己的内部材料——它只进问答文件，不进公开文章。
  • 问答文件是该案例的主档：老师原题、数字速查、逐题中英答案、决策选择与代价、启示、课堂上可说的判断、课前投票——全部写入此文件，不要只留在对话里。文章是另一次对外交付，结构可不同，但判断与数字须与主档一致。
  • 存为 <预习目录>/YYYY-MM-DD_<案例简名>_预习问答.md，并在回复里给出完整路径。

2. 预习文章

标题规则

哈佛预习｜<课程类别>：<案例名> —— <主题短语>

  • <课程类别>：中文一个词，后面不加"案例"二字：Market-Facing Functions → 市场营销、Leadership → 领导力、Strategy → 战略、Finance → 金融、Operations → 运营、Innovation → 创新、Negotiation → 谈判。读者一眼知道是哪门课，同一单元的文章成系列。
  • <案例名>：保留原案例的公司 / 主体名，如 Belden、Olay、Cynthia Carroll at Anglo American。
  • <主题短语>：一个短语或一句短句，像书的章节名——说清这篇在讨论什么问题，一般 4–14 个字，最多一个逗号或顿号。可以是问题（"客户旅程应该如何设计"）、判断（"品牌即承诺"）、或"何时、如何 + 动作"（"何时、如何把公司卖个好价钱"）。不写成完整长句、不堆条件状语、不追求"张力词"。有力的长句留给正文的 ### 小标题。句末不加标点。
  • ✅ 哈佛预习｜战略：Axel Springer —— 转型中，选择适合自己的并购标的
  • ✅ 哈佛预习｜市场营销：Bajaj Finance —— 客户旅程应该如何设计
  • ✅ 哈佛预习｜金融：Nantucket Nectars —— 何时、如何把公司卖个好价钱
  • ✅ 哈佛笔记｜市场营销：Olay —— 品牌即承诺
  • ❌ 哈佛预习｜战略案例：Axel Springer —— 大交易丢了之后，别用更贵的安慰奖疗伤，买一家还在长、能按自己打法养的公司（课程后多了"案例"；后半句是一整段话，不是标题）
  • ❌ 哈佛预习｜Belden —— 冰山在融化（悬念）
  • ❌ 哈佛预习｜Belden 的数字化转型（丢了课程与破折号结构）
  • 标题里若用了典故，正文开头要有一句点出出处。
  • 原本想写进标题的那句"有力的长判断"，放到第一个 ### 小标题或「写在课前」里。

结构模板

骨架见 references/article_template.md。

  1. frontmatter：title / date / author / status: 草稿（课前版） / case: <案例全名、编号、作者；授课老师、课程>
  2. 开头两行交代课程与案例。第一行：单元、老师、课程，末尾中文逗号；第二行：案例英文全名，末尾中文句号。不写"第几个"、不写出版年份或案例编号： Unit 3，Das Narayandas 教授 Market-Facing Functions， Bajaj Finance: Building an Omnipresent Financial Services Firm。
  3. 一两句定调（这是一个什么故事），然后 以下，enjoy：。
  4. ## 案例梗概：不浓缩，完整讲故事——来路、转折、动作、数字、原话引用、结尾的决策点。4–6 段是正常的。决策题用有序列表列出，每题带数字。
  5. ## 我的思考：4–6 个 ###，每个小标题就是本节的判断句（有力的短句，不是名词、不是问句、不用"关于"）。不编号。每段至多一处 **加粗**，一处不超过一句。自己的延伸判断单独成段，用"我自己的理解是 / 我自己的倾向是"切换。老师提问里的决策题，在这里给出明确选择和理由。
  6. ## 对我的借鉴（可按自己的身份改名，如"对创业的借鉴"）：4–6 条，每条一句加粗的判断 + 两三句展开。文章是公开的：只谈方法与原则，不写内部收入、费率、客户、融资等信息（这些留在问答文件）。
  7. ## 写在课前：课前最认同哪一句，到此为止。安静开放，不喊口号。

语感

  • 克制，短段落，一两处安静的诗意落点；
  • 破折号（——）可以多用，但不要用"读到这里我停顿了一下"这类表演式旁白；
  • 哲学或书籍引用须精准到人和书；
  • 少"AI 味"：排比句、总分总、"首先 / 其次 / 最后"、空洞金句都删掉；
  • 可与同一单元的前一篇做一次对照（"Olay 是……，Belden 正好相反……"）。

落盘

<文章目录>/YYYY-MM-DD_哈佛预习_<课程类别>：<案例名> - <主题短语>_草稿.md

  • 标题里的 ｜ 在文件名里换成 _；—— 换成 -（空格短横空格）。
  • 配图目录与文章同名加后缀：<文章文件名去.md>_配图/。
  • 改标题时同步改文件名、配图目录和 Markdown 里的图片相对路径。

3. 配图

风格固定，内容随案例变化。 不按"金融 → 天平 / 控制权 → 钥匙"套用通用意象。先提取本案的具体事实与机制，回看最近 3–5 篇配图避免重复，再写提示词。

固定风格：纯白底、柔灰铅笔线稿、不画人、不画任何文字、大量留白；哈佛元素（如 Baker Library）以远景、局部或空间关系融入头图；全图只有一处压暗的哈佛红 #A51C30 点睛，落在对应判断的那个细节上。

图 比例 意象 红色落点
头图 16:9 本案的产品、业务对象或关键场景为主视觉，融入哈佛建筑 对应该案判断的具体细节
图 01 4:3 正文第一个重要机制，用案例物件的关系或状态表达 变化发生的位置
图 02（可选） 4:3 另一个独立判断 同上

手绘感：提示词必带 Hand-drawn pencil sketchbook drawing、visible light construction lines、cross-hatching in the shadows、varied pencil pressure、a few loose exploratory strokes、soft 2B graphite, no ink outlines，并给出轻微透视（three-quarter angle）与一两个前景细节。不要正立面、全对称的矢量感。

验证过的提示词与选图方法见 references/image_prompts.md——只借用其风格措辞，主体和构图必须从新案例重新提炼。用你环境里可用的图像生成工具出图；文件名用 头图_<意象>.png / 图01_<意象>.png，插在对应 ### 小标题之后、正文之前。

去标题检验：遮住文章标题后，如果这张图几乎不改就能放到别的案例里，换一个更具体的方案。

4. 发布前自查

  • 绝对化用语、对第三方的负面定性、数据出处是否清楚；
  • 「对我的借鉴」一节是否泄露了内部信息（收入、客户、融资、未公开合作）；
  • 案例中的引文是否与原文一致；数字是否与问答文件一致；
  • 回复里给出：问答文件路径、文章路径、配图清单、标题。不替用户对外发布。

一次完整示例（Belden）

  • 问答：Q1 融化的冰山 → Q2 工业自动化业务在集团的分量 → Q3 改了 / 没改什么 → Q4 三个决策 → Lessons → 对我的联想
  • 标题：哈佛预习｜市场营销：Belden —— 从卖零件到卖方案
  • 小标题：最难的转型，是在报表最好看的那一年开始的 / 卖方案换的不是话术，是你见的人 / 先收钱的审计，是定价权的起点 / 没改的那一半，正在变成新的瓶颈 / 三道题其实是一道题：把例外变成规则 / 销售回本快，研发回报大，所以不是二选一
  • 配图：头图 Baker Library + 线缆卷盘爬上台阶（红：接头）；图 01 水下被掏空的冰山（红：水线）；图 02 会议桌上的一卷线缆（红：接头）

个性化设置

第一次用之前，在本文件里替换这几处：

  • <预习目录>、<文章目录>：你想把问答和文章存在哪里（如 notes/预习/、articles/）；
  • frontmatter 里的 author；
  • 「对我的借鉴」一节的名字，以及问答里「对我自己工作的联想」可以参考的材料；
  • 如果不是哈佛，把标题前缀 哈佛预习 换成你的课程名，配图里的哈佛元素换成你学校的建筑与校色。
